# 스윙 라이브 런북 (`sw-live`)

설계: `docs/superpowers/specs/2026-10-10-swing-live.md`. 코드: `src/swing_it/live/` — 판단은 `strategy.py` 하나,
런타임(`runtime.py`)은 그 결정을 주문으로 옮기고 체결을 장부로 되돌리는 배관이다.

> **기본은 페이퍼다.** 이 전략은 아직 표본 밖 판정이 없다(`research/logs/sepa_explore/CONVERGENCE.md`). 실계좌 주문은
> 사람이 §6 체크리스트를 채우고 `--execute --confirm-real` 두 플래그를 직접 줄 때만 나간다. 크론은 설치돼 있지 않다.

## 1. 모드

| 플래그 | 모드 | 시세 | 계좌 조회 | 주문 |
|---|---|---|---|---|
| (없음) / `--paper` | `paper` | 키움 REST 실시세(읽기) | 없음(모의 브로커) | 프로세스 밖으로 안 나감 — 코어 `PaperBroker` 를 파일로 영속 |
| `--dry-run` | `dry-run` | 실시세 | 실계좌 잔고(kt00018) | POST 안 함(`KiwoomBroker(dry_run=True)`) |
| `--execute --confirm-real` | `live` | 실시세 | 실계좌 | **실주문**(지정가만, 거래소 KRX) |

- `--execute` 나 `--confirm-real` 하나만 주면 거부(종료 코드 2). `--paper`/`--dry-run` 과 섞어도 거부. 환경변수로는 못 켠다.
- `--ignore-clock`(작업 시간창 무시)은 페이퍼 리허설 전용.
- 키움 서버: `SWING_KIWOOM_IS_MOCK=true` 면 모의서버, 기본 실서버(페이퍼도 실시세가 필요해서). 앱키 `KIWOOM_APP_KEY`·`KIWOOM_APP_SECRET`.
- 상태는 모드별로 완전히 분리: `data/live_swing/{paper,dry-run,live}/`. 페이퍼 상태로 실계좌를 굴릴 수 없다(스냅샷 모드 검사).

## 2. 하루 일정(KST, 평일)과 작업

예시 크론: `deploy/crontab.swing-live.example`. 키움 겹침 시간(06:30~07:30, 10:00~10:15, 16:00~16:50)을 피한다.

| 시각 | 작업 | 하는 일 |
|---|---|---|
| 07:35 | `signal` | DB(`KR_QUANT_DB`)에서 신호일 d(=직전 거래일) 패널 → `scan` → `plan_entry`. **중단 조건**: DB 최신일 ≠ 키움 기준 종목 직전 거래일(daily_finalize 미완), 신호일 NXT 보정(`krx_patched`)이 안 돎, 신호 원천 오류(예: `features.signal_panels_for` 없음 — 알림에 이름이 찍힌다). 보정 안 된 후보는 뺀다. **보유 종목은 d 의 KRX 종가(DB 보정본, `swing_it.krx_session`)로 종가 기준 결정을 전부 한다**: 돌파 실패(익절 전 종가 < 피벗 → 오늘 시가 전량, 설계 §6), MA50 추적(익절 뒤 종가 < MA50 → 오늘 시가), 최대 보유 120일 안전 상한. 결정은 장전 동시호가 매도 의도가 된다. 같은 종가로 **d 장 마감 자산을 확정**하고 다일 낙폭 킬·일 손실 킬을 판정한다. |
| 08:35 | `preopen` | 휴장(주말·`holidays.txt`) 확인 → 계좌 **기준선**(사용자 몫 = 계좌 − 전략 장부) → 전일 결정 매도를 장전 동시호가에(지정가 = 기준가 × 0.9 호가 올림, 단일가에 체결) → 킬 확인 → 지정가 매수(min(피벗×1.05, 상한가−1틱) 호가 내림). 사용자 보유 종목은 사지 않는다. 슬롯·현금은 `sizing.allocate`. |
| 09:02 | `open-check` | 세션 확인(**신선한 증거**만: ka10081 기준 종목 오늘 봉, 또는 오늘 일자가 찍힌 시세 — 시가가 있다는 것만으로는 확정하지 않는다, 검토 F4) → 시가 체결 반영(페이퍼는 `Quote(09:00, 시가)` 주입) → 미체결 매수 취소(추격 없음) → 체결가로 손절·목표 확정(시가 ≤ 수축 저점이면 즉시 청산) → 보유 포지션 시가 판단(갭 손절·갭 익절·본전). **봉도 시세도 없으면 "휴장 의심"**: 주문은 그대로 두고 경보만, 판정은 monitor 틱마다 다시(검토 M3). **`open_pric` 이 없으면** missed 로 치지 않는다: 경보 + 주문 유지, 09:05 이후 monitor 가 현재가를 단일가 대용으로 판정(검토 M4). |
| 09:05~15:19 | `monitor` | 60초마다 보유 종목 현재가(ka10001, KRX) → `on_quote` → 손절·절반 익절·본전. 매도는 **터치 즉시 지정가 = 현재가 − 1틱**, 1분 안에 안 채워지면 취소 후 현재가 × (1 − 0.5%×(시도−1)), 상한 3%. 거부·차단이 3회 이어지면 그 매도를 멈추고(`halted`) error 경보 — 다음 preopen 이 한 번 다시 시도(검토 M1). 10:00~10:15 은 180초. 크론이 10분마다 다시 띄워도 잠금이 막는다. |
| 15:21 | `close` | 오늘 아직 못 판 매도 의도(연속매매에서 안 채워진 손절·익절·본전)를 종가 동시호가에 낸다(지정가 = 현재가 × 0.9 호가 올림 → 단일가 체결). **종가 기준 결정은 하지 않는다** — 시간 손절은 폐지됐고(설계 §6), 돌파 실패·MA50 추적·최대 보유 상한은 다음날 `signal` 이 정한다. |
| 15:40 | `eod` | **장부 정리·잠정 보고만**: 종가 동시호가 체결 반영(페이퍼는 `Quote(15:30, 종가)` 주입; 키움은 잔고 차이 + ka10001 가격 **추정**) → 남은 주문 만료 → 잠정 평가 알림. MA50 추적·자산 확정·낙폭 킬은 **하지 않는다**(다음날 07:35 `signal`) — 15:31 이후 ka10001 현재가가 KRX 15:30 단일가라는 검증이 없다(감사 L5). |
| 아무 때 | `status` | 스냅샷 요약(브로커·키움 호출 없음). |
| 아무 때 | `reconcile` | 계좌 = 전략 장부 + 기준선 사용자 몫인지 대조. **고치지 않고 보고만**. |

모든 작업은 멱등이다(같은 날 다시 돌려도 중복 주문 없음). `signal`·`eod` 를 강제로 다시 돌리려면 `--force`.
시간창 밖·잠금 경합으로 건너뛴 작업은 종료 코드 2 + warn 경보(검토 M7) — 크론 지연을 조용히 넘기지 않는다.

**주문 멱등성(검토 C1·F1·F2).** 모든 주문은 POST **전에** 원장·스냅샷에 `intent`(클라이언트 키 `oid`)로 저장된다. 다음 작업 시작의
대조(`_resume_orders`)는 `intent` 와 **번호 없는 `unknown`**(접수 뒤 응답 유실)을 브로커 미체결과 맞춘다 — 같은 종목·방향 중 우리 원장에
없는 번호가 **정확히 하나**이고, 그 번호가 오늘 우리가 아는 최대 번호보다 **크며**(당일 계좌 순번), 수량·가격이 같을 때만 이어받는다
(error 경보: 사람이 HTS 로 확인). 후보가 둘 이상이거나 순서를 못 가리면(사용자가 같은 주문을 걸어 둔 경우 등) `needs_human`, 없으면
`unknown` 그대로 — 두 경우 모두 그 종목의 **신규 진입을 막고**(`blocked_codes`) error 경보. 번호 없는 주문은 브로커 취소가 확인되기 전엔
`expired` 로 바꾸지 않는다(살아 있을 수 있다 — 사람이 HTS 에서 확인·취소). 어느 쪽이든 **다시 POST 하지 않는다.** 풀기:
`sw-live release-order --oid <oid>`(예약·종목 차단 해제, 브로커엔 아무것도 안 보냄). 장부에 있는데 원장 포지션이 없는 종목(체결 반영과
저장 사이 크래시)도 시작 시 error 경보.

### 첫 페이퍼 실행

페이퍼를 시작하기 **전에** 사람이 한 번 확인할 것(검토 §8 — 틀리면 2주 페이퍼가 "진입 0 / 무감시" 로 조용히 끝난다): 겹침 시간
밖에서 `ka10001` 한 번 조회해 `open_pric`·`base_pric` 이 있는지, 6자리 코드 응답이 `_AL`(통합) 과 다른지(= KRX) 본다. 없으면
`brokers.RestQuoteProvider` 필드명을 고친다. 런타임은 `open_pric` 이 없으면 경보하고 09:05 이후 현재가로 대신하지만, 그 전제가 틀린
채 페이퍼를 돌리면 체결 모형이 백테스트와 어긋난다.

```bash
cd ~/git/swing-it
uv sync                                  # sw-live 엔트리포인트
set -a; . ../quant-airflow/.env; set +a  # KIWOOM_APP_KEY / KIWOOM_APP_SECRET / KR_QUANT_DB — 비밀은 환경변수 또는 이 파일로만(레포 안 .env.* 는 gitignore)
.venv/bin/sw-live status                 # 배너·경로 확인(키움 호출 없음)
.venv/bin/sw-live signal --capital 10000000    # 07:31~08:29 에만(시간창)
```

시간창 밖에서 리허설: `--ignore-clock --asof YYYY-MM-DD`(페이퍼만). 결과: `data/live_swing/paper/` 의
`state.json`(스냅샷)·`ledger.jsonl`(사건 원장)·`book.jsonl`(장부)·`orders.jsonl`(OMS 주문 로그)·`paper_broker.json`·`logs/YYYY-MM-DD.log`.

### 휴장일

`data/live_swing/holidays.txt` 에 `YYYY-MM-DD` 한 줄씩 — **사람이 매년 KRX 휴장일 전부를 적는다. 이것이 휴장의 첫 번째(사실상 유일한)
방어선이다.** 모든 작업이 시작 시 파일에 올해 날짜가 있는지 확인하고 없으면 경보한다(검토 F4). 파일에 없는 휴장일이면: 장전 주문은
나가고(실계좌는 키움이 거부·소멸), 09:02 부터 세션이 "의심" 으로 남아 체결 판정·보유일 전진을 하지 않으며(ka10001 이 직전 거래일 값을
캐시로 줘도 **오늘 일자가 찍힌 증거가 없으면 열린 것으로 보지 않는다**), eod 가 주문을 거두고(실계좌에서 이미 사라진 주문은 `released`),
다음 날 계획이 만료된다. `signal` 은 키움 기준 종목 일봉으로 직전 거래일을 정해 휴장을 정확히 건너뛴다.

## 3. 안전 설계

- **청산은 막지 않는다.** 정지 파일·낙폭 킬·일 손실 킬은 신규 매수만 막는다(코어 OMS 규약 — 청산을 막으면 포지션이 무감시로 남는다).
- **사용자 주식은 사지도 팔지도 않는다.** 아침 기준선에서 사용자 몫이 있는 종목은 매수하지 않고, 매도 수량은 전략 장부 보유 −
  걸린 자기 매도 잔량까지만이다. 장부에 없는 종목은 팔지 않는다.
- **체결 판정(키움)**: `ka10076` 체결 조회가 미검증이라 코어 `KiwoomBroker(fills_verified=False)` 는 체결을 주지 않는다. 런타임은
  **잔고 차이**(계좌 − 기준선 − 장부)를 **브로커에 살아 있는 자기 주문(submitted/partial/unknown)의 잔량까지만** 체결로 본다
  (감사 L4). 취소·만료된 주문에는 배정하지 않고, 장전 주문은 09:00 단일가가 지정가 안일 때만 후보다. 가격은 추정(동시호가 = 단일가,
  장중 매도 = max(지정가, 현재가), 신규 매수 = 계좌 평단)이고 원장에 `price_estimated: true` 로 남는다. 설명 안 되는 차이는
  장부에 넣지 않는다: 늘어난 주식은 **사용자 몫으로 기준선에 더하고**(전략은 그 주식을 절대 팔지 않는다), 줄어든 주식은 기준선을
  같은 만큼 빼서(음수 = 계좌에 전략 몫이 모자람) `mismatch` 사건 + 알림 → 사람이 `reconcile` 로 확인.
  브로커 미체결이 그 주문의 잔량을 알려 주면 **지금까지 체결된 양까지만** 배정한다(검토 M6 — 부분 체결 + 같은 날 사용자 매수의 과잉
  귀속 폭을 줄인다; 잔량 조회가 안 되면 주문 잔량 전체가 상한이다).
  **취소 거부(= 이미 체결?)는 잔고 한 번으로 단정하지 않는다**(검토 C2): 주문을 `fill_pending` 으로 두고 잔고를 3회(5초 간격, ≥10초)
  다시 읽으며 미체결 조회로 대조한다. 그동안 그 수량은 예약된 채라 **같은 수량을 다시 팔지 않는다.** 체결도 미체결도 설명하지 못하면
  (사용자 HTS 취소·휴장 소멸·취소 API 오류) `released` 로 **예약을 풀고** error 경보 — 청산은 다시 나간다(검토 F3: 예약이 손절을 막는
  시간은 이 창 ≈10초뿐이다). 뒤늦게 체결이 잔고에 나타나면 "설명 안 되는 차이" 경보로 드러난다. 수동 해제: `sw-live release-order --oid <oid>`.
  **구분 불가능한 경우가 남는다(잔고 차이 방식의 본질적 한계)**: (1) 전략 매도 주문이 걸려 있는 동안 사용자가 같은 종목을 같은 수량 팔면
  그 매도가 전략 체결로 읽힌다(전략 주식은 남아 있는데 장부에서 사라짐 → 다음 날 기준선이 사용자 몫으로 분류 → 무감시). (2) 전략 주문이
  부분 체결된 날 사용자가 같은 종목을 사면, 브로커 잔량 조회가 안 될 때 사용자 매수 일부가 전략 몫으로 과잉 귀속될 수 있다(→ 손절 때
  함께 팔린다). **공유 계좌 규칙: 전략 보유 종목과 당일 진입 후보(`sw-live status`)는 수동 매매하지 않는다.** 실계좌 전에는
  `ka10075`/`ka10076` 을 실호출로 검증해 주문번호 기준 체결로 바꾸는 것이 전제다(§6).
- **주문 가드**(코어 `OrderGuard`): 매수마다 수량 상한 = ⌊자산 × 12% / 지정가⌋, 가격 밴드 ±6%(전일 KRX 종가 대비), 프로세스당 주문
  20건(작업마다 새 프로세스라 "일일" 이 아니다 — 일일 멱등성은 상태가 지킨다). 그 위에 런타임이 명목 상한(자산 × 10% × 1.07)을 한 번 더 본다.
  밴드 실측(검토, 원시 돌파 사건 9,853건 2024-01~2026-09): 지정가 = min(피벗×1.05, 상한가−1틱) 은 돌파일 종가 아래로만 떨어지므로 **아래쪽
  밴드만 걸린다** — 종가/피벗 > 1.117 인 **15.3%** 는 지정가가 전일종가×0.94 아래라 가드가 거부한다(백테스트도 그 사건은 11.7% 갭하락이
  아니면 미체결이라 패리티엔 무해; 로그에 `order_blocked` 로 남는다). 41.4% 는 지정가 < 전일종가(갭하락에만 체결).
- **매도 예약 수량은 우리 원장으로** 센다(검토 M2): 같은 종목에 사용자가 걸어 둔 미체결 매도는 전략 손절을 막지 않는다.
- **시간창**: dry-run·live 는 작업별 시간창 밖이면 주문하지 않고 종료 코드 2(장전 매수를 10시에 내면 추격 매수가 된다).
- **KRX 정규장만**: 시세 코드는 6자리(= KRX; `_NX`·`_AL` 접미 거부), 주문 거래소 `KRX`. 키움 일봉(ka10081)은 2026-09-14 부터
  NXT 야간 체결이 섞여 가격에 쓰지 않는다(날짜만). MA50 은 DB 보정본(`swing_it.krx_session`) 종가 + eod 의 KRX 종가.
- **UNKNOWN 주문**(응답 없음): 재시도하지 않는다. 알림 → 사람이 미체결·잔고로 확인.
- **잠금**: 모드당 하나(`swing_live.lock`). 두 작업이 같은 상태를 동시에 고치지 않는다. monitor 가 돌고 있으면 다른 작업은 최대 120초 기다린다.
- 토큰 logout/revoke 를 부르는 코드는 없다(다른 데몬과 앱키 공유).

## 4. 킬 스위치

| 무엇 | 파일/조건 | 효과 | 해제 |
|---|---|---|---|
| 수동 정지(전역) | `data/swing_STOP` 생성 | 모든 모드 신규 진입 정지 | 파일 삭제(비고정 — 다음 작업부터) |
| 다일 낙폭 킬 | 장 마감 자산 ≤ 고점 × 0.85 (다음날 07:35 signal 이 DB 종가로 판정) | live: `data/swing_STOP`, 페이퍼: `data/swing_paper_STOP`, dry-run: `data/swing_dryrun_STOP` 생성 | 원인 확인 후 파일 삭제 = 확인(ack). 다음 signal 에서 고점을 그때 자산으로 다시 잡는다. **live 는 전역 정지 파일과 같은 파일**이라 다른 이유로 만든 `swing_STOP` 을 지우는 것도 낙폭 ack 로 읽힌다 |
| 일 손실 킬 | 직전 거래일 자산 변동 ≤ −3% (코어 `KillSwitch`) | 그날 신규 진입 정지 | 다음 거래일 자동 |

자산은 **전략 자본 기준**(첫 실행 `--capital` + 실현손익 + 평가손익)이다 — 공유 계좌 전체가 아니다.

## 5. 복구

- **상태 손상**(`state.json` 파싱 실패·모드 불일치·스냅샷 없이 원장만 있음): 모든 작업이 종료 코드 3 + 알림. `state.json.bak`(직전 판)과
  `ledger.jsonl` 을 보고 사람이 고친다. 코드가 추측해서 복구하지 않는다.
- **monitor 가 죽음**: 크론이 10분 안에 다시 띄운다. 스냅샷에 걸린 매도 주문·매도 의도가 있으니 이어서 재가격한다.
- **작업을 놓침**: `open-check` 를 놓쳐도 monitor 가 ka10001 시가로 그날 시작 판단을 한다. `close` 를 놓친 시간 손절은 eod 가 다음날
  시가 매도로 미룬다. `eod` 를 놓치면 그날 MA50 추적 결정이 없다(다음 eod 에서 본다) — 보유일이 4일 넘게 비면 알림.
- **잔고 불일치**: `sw-live reconcile --dry-run`(또는 해당 모드). 원인이 사용자 수동 매매면 다음 날 기준선이 흡수한다. 전략 장부가 계좌보다
  크면(전략 몫이 사라짐) 사람이 확인 — 장부를 손으로 고칠 때는 `book.jsonl` 에 보정 체결을 추가하고 `state.json` 포지션 수량을 맞춘다.
- **signal 을 하루 놓침**(크론 미실행·daily_finalize 지연·시간창 밖): 다음 signal 이 마지막 평가일 이후 **모든 거래일**의 DB 종가를 차례로
  평가해 추적 청산·자산 행·킬을 따라잡는다(검토 M5; 하루 늦은 시가 매도). 배치는 결손 길이만큼 커진다(상한 없음, 15거래일 넘는 결손은
  경보 — m10). 결손 중 `day_no` 는 오르지 않아 시간 손절·최대 보유가 결손 길이만큼 늦는다. DB 최신일이 직전 거래일보다 이르면 신규 진입만 중단하고
  있는 날짜까지의 보유 결정·자산은 수행한다.
- **잘못 켠 실주문**: `data/swing_STOP` 을 만들어 신규 진입을 멈춘다. **monitor·close·eod 크론 줄은 남긴다** — 지우면 보유 포지션이
  무감시가 된다. 포지션까지 정리하려면 HTS 에서 수동 청산한 뒤 `reconcile` 로 장부 차이를 확인하고 `state.json` 포지션을 사람이 닫는다.
- **`reconcile` 시각**: monitor 가 09:05~15:19 잠금을 쥐므로 장중엔 돌지 않는다(120초 대기 후 rc 2). 15:50 크론 또는 장외에 돌린다.

`signal` 이 받은 `SignalBatch.vetoed`(거부된 후보)와 `veto_info`(코드 → `neg5`/`neg20` 악재 수·사유)는 **주문 없이** 섀도 포지션

  **근사다**: ka10001 일중 필드는 미검증이고 15:40 현재가는 KRX 종가로 검증되지 않았다(L5) — 섀도는 거부군 vs 진입군 비교용이지
  실포지션 판단에는 쓰지 않는다. 세션이 확정되지 않은 날(휴장 의심)엔 섀도도 건드리지 않는다.
- `sw-live status` 의 `뉴스 거부권:` 줄이 합격 바를 그대로 보여 준다 — `거부군(섀도) n·평균순수익·손절률 | 진입군(실제) n·평균순수익·
  손절률 → 합격 바 충족/미충족(거부 n/30건)`. 순수익률 = 장부 실현 순손익 / (진입 수량 × 진입가), 닫힌 포지션만. 합격 바(NEWS_VETO.md):
  전진 6개월 또는 거부 30건 이상에서 거부군 평균 순수익 < 진입군 **그리고** 거부군 손절률 ≥ 진입군.

## 7. 라이브-백테스트 차이

**손절 체결가(감사 L1).** 백테스트(`swing_it.live.backtest`)는 손절을 손절가 그대로(갭이면 시가) 체결한다. 라이브는 60초 폴링으로
`현재가 ≤ 손절가` 를 본 뒤 **현재가 − 1틱** 지정가를 내고, 1분마다 0.5%씩 내려 최대 3% 까지 재가격한다. 이 전략은 손절 비율 ~60%,
d ≈ 10% 라 손절당 미끄러짐이 트레이드 기대수익에 직접 들어간다.

실측(검토자, `minute_bars` 2025-08-01~2026-10-08; 원시 돌파 유니버스 진입 2,324 중 표본 600 → 분봉 있는 574, 20거래일 내 손절가 터치 353,
그 중 시가 갭 45 제외 **장중 터치 308**; 폴러 모형 = 60/180초 간격으로 분봉 종가를 현재가로 보고 첫 `현재가 ≤ 손절가` 에서 현재가 − 1틱 체결):

| 항목 | 60초 폴링 | 180초 폴링 |
|---|---|---|
| 터치 당일 감지 / 다음날 이후 감지 / 창(20일) 안 미감지 | 87.0% / 11.0% / 1.9% | 85.4% / 12.3% / 2.3% |
| 감지 시점(터치 분봉 이후, 중앙값) | 1분 | 3분 |
| 체결가/손절가 − 1 (감지된 것, 평균 / 중앙) | **−46bp / −15.5bp** | −51bp / −21bp |
| 같은 분위 p25 / p10 | −42bp / −107bp | −48bp / −125bp |
| 트레이드당 기대수익 영향(손절 비율 ~60%) | **≈ −0.28%p**(평균 기준; 중앙값 기준 −0.09%p) | ≈ −0.31%p |
| 첫 지정가(현재가 − 1틱) 1분 내 체결 비율 | _(분봉으로는 못 잰다 — 페이퍼 원장 `attempt` 분포로 채울 것)_ | 같음 |

원인: 터치 분봉의 종가 중앙값은 손절가 **+4.9bp** — 저가만 닿고 되돌린 분이 절반이라 폴러는 그 분엔 못 보고 1분 뒤(중앙) 더 낮은
가격에서 본다. 호가·대기열은 포함되지 않았으므로 실제는 몇 bp 더 나쁘다. 미감지 1.9% 는 창 끝 가격이 손절가 위(중앙 +15%)라 안 잡힌
편이 유리했던 표본 특성이다. 백테스트 민감도는 손절가에 −46bp(평균) / −107bp(p10) 를 붙여 두 줄로 보고한다(`backtest.py` 는 전략
모듈 소관). 스크립트·행 데이터: 검토자 scratchpad `review_runtime/stop_poller.py`, `stop_poller_rows.csv`(레포 밖).

**그 밖의 차이.**
- 장중 폴링(60초) 사이의 터치는 놓친다(일봉 모형은 고가·저가로 판정). 반대로 라이브는 갭 상승 익절 뒤 같은 날 손절까지 빠지면 이미 절반을 팔았다.
- 종가 기준 청산(돌파 실패 `종가 < 피벗`, MA50 추적, 최대 보유 상한)은 백테스트와 같은 DB 보정 종가로 판단하되 **다음날 07:35** 에
  한다 — 결과는 같다(둘 다 "d 종가 조건 → d+1 시가 매도"). 시간 손절은 없다(설계 §6). 15:20 `close` 작업은 결정을 하지 않고 못 판
  의도만 종가 동시호가에 낸다.
- 정수 주라 1주 포지션은 절반 익절이 0주다(상태는 익절 뒤 단계로 넘어간다 — `strategy.py`).
- 키움 체결가는 추정이다(§3). `ka10076` 을 모의계좌로 확인하면 `KiwoomBroker(fills_verified=True)` 로 바꿀 수 있다.
- MA50 종가는 DB 수정주가(보정본)라, 보유 중 액면분할이 있으면 eod 전까지 섞인다(다음날 signal 이 새로 받는다).
