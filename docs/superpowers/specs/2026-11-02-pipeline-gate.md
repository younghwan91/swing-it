# 파이프라인 11단계 가드레일 — 설계 (2026-11-02)

**완료 조건:** (a) 앞 단계 증거가 없거나·실패했거나·낡은 러너는 예외를 던지고 돌지 않는다. (b) study·stage 를 선언하지 않은 새 연구 러너는 CI 에서 실패한다. (c) 기존 연구 3개가 **실제 상태 그대로** 원장에 있다. (d) 테스트가 (a)~(c)를 증명하고, 각 가드를 제거하면 실제로 실패한다. (e) quant-reviewer 관점 자가 점검을 남기고, 전체 테스트·ruff·`check_guardrails` 가 초록이다.

사용자 요청: "내가 보내준 이미지의 프로세스들이 순차적으로 이루어지도록 가드레일을 구축해", "모듈화 + 가드레일화". 이미지는 11단계다 — 1 유니버스 → 2 데이터 → 3 알파 발굴 → 4 알파 검증(IC/ICIR) → 5 ML 수익률 예측 → 6 팩터 위험모델 → 7 포트폴리오 최적화 → 8 거래비용 모델 → 9 백테스트 → 10 주문 실행 → 11 성과 기여·모니터링.

독자용 설명은 `docs/PIPELINE.md` 다. 이 문서는 왜 이렇게 정했는지만 적는다.

## 주 세션이 정한 것

- 패키지 `src/swing_it/pipeline/`: `stages.py`·`gate.py`. 처음에는 `contracts.py`·`s01_universe.py`~`s11_attribution.py` 도 뒀지만 지웠다 — 맨 아래 "모듈화" 절.
- 연구별 덧붙이기 전용 원장 `research/logs/<study>/PIPELINE.jsonl`. `require_stage`·`record_stage`, CLI `python -m swing_it.pipeline status|record|verify`.
- 규칙: fail 은 그 단계의 새 pass 전까지 뒤를 막는다. skip 은 사유가 필수다. 앞 단계를 다시 기록하면 뒤 단계 pass 는 stale 이다. 4·5·9 의 pass 는 검증 문서 참조가 필수다. 10 은 사용자 승인 기록과 전진 페이퍼 증거가 필수이고 추론하지 않는다. 증거 해시가 어긋나거나 파일이 없으면 stale 이다.
- 러너는 파일 위에 `PIPELINE = ("<study>", <stage>)` 를 적고 데이터를 읽기 전에 `require_stage` 를 부른다. `check_guardrails.py` 가 강제하고, 오늘 있는 파일은 늘어나지 않는 면제 목록에 둔다.

## 일부러 강제하지 않는 것

- **판정의 옳음.** 게이트는 기록의 순서와 증거 해시만 본다. 검증 문서가 실제로 무엇을 말하는지는 읽지 않는다 — 리포터-not-판정기(GUARDRAILS §8)이고, pass 를 거짓으로 적는 것은 코드로 못 막는다.
- **사용자 승인의 진위.** 날짜와 인용문이 있는지만 본다. 인용이 진짜인지는 리뷰로 확인한다.
- **시장 중립·벤치마크 의무.** 기관이 아니다. 순위 북은 6~7단계를 건너뛰어도 된다.
- **증거의 질.** `README.md` 도 증거로 적을 수 있다. 더 조이지 않는다 — 공개 커밋이 비용이고, 나머지는 개인 연구의 자유다.
- **면제 목록에 있는 파일의 내용 변경.** 이름만 본다. 이 파일들을 고쳐 새 연구를 돌리는 것은 리뷰로 잡는다.

## 건드리지 않는 것

- `src/swing_it/price_adjust.py` 는 Airflow 가 라이브 마운트로 돌린다. numpy·pandas·표준 라이브러리 밖을 import 하면 거기서 죽는다. 새 패키지에 의존하지 않고, 테스트가 이를 고정한다.
- 기존 러너 동작과 바이트 동일 재현. 러너를 옮기거나 고치지 않는다.
- `src` 는 `research` 를 import 하지 않는다(린트 (a)). 단계 표의 연구 코드 참조는 경로 문자열이고, 테스트가 그 경로와 심볼의 실재를 확인한다.
- 키움 호출·주문. 10단계에는 구현이 없고 `docs/execution/DESIGN.md` 를 가리킨다.

## 자가 점검 (2026-11-02, quant-reviewer 관점 — 구현자 본인의 점검이고 독립 리뷰가 아니다)

"이 가드를 어떻게 피할까"를 직접 시도했다.

| 시도 | 결과 |
|---|---|
| 실패한 단계를 skip 으로 다시 적기 | **뚫렸다** → 거부로 고침(결정 15) |
| 같은 B_verified 로 4단계 pass 적기 | **뚫렸다** → 거부로 고침(결정 15). 다른 문서로 거짓 pass 를 적는 것은 여전히 못 막는다 — 리뷰 몫 |
| fail 마지막 줄을 손으로 pass 로 고치기 | **체인이 못 잡았다**(다음 줄이 없으면) → 줄마다 `sha` 를 더했다 |
| 체인을 맞춰 모양이 어긋난 줄 덧붙이기 | KeyError 로 죽었다 → `LedgerCorrupt` 로 고쳤다 |
| 러너를 1단계로 선언하고 백테스트 돌리기 | **뚫렸다** → 린트로 막았다(결정 16). 그 밖의 잘못된 단계 선언은 못 막는다 |
| `require_stage(study, 10)` 만으로 주문 경로 열기 | **뚫렸다** → `require_execution_approval` 분리(결정 9) |
| 조건문·try 안에서 게이트 부르기, 다른 인자 넘기기, 데이터 먼저 읽기 | 린트가 잡는다 |
| 연구 이름을 바꿔 fail 피하기 | 못 막는다 — 위 "강제하지 않는 것" |

이 표 뒤에 독립 리뷰가 있었다(CRITICAL 0, MAJOR 6): 린트 범위, 게이트 전 데이터 접근, 원장 끝 줄 잘라내기, `s03` as-of 위반, `s02` 의 거짓 인자, ML·PR #18 머지 경로. 결정 8·9·12·14·16~21 이 그 반영이다.

소급 기록의 정직성은 숫자마다 원문과 대조했다(`B_verified.md`·`B_parity.md`·`A1_repaired.md`·`B_feasibility.md`·`PEAD_FORWARD_PREREG.md`). `pead_forward` 4단계 skip 은 판단이 들어간 곳이라 사유에 "표본 안 검증 미통과"를 그대로 적었다.

실제 Postgres 읽기 전용 스모크: `s02_data` → `s03_alpha` → `s04_alpha_validation` 이 계약 위반 없이 돈다. `s02_data` 의 지문을 2019-01-01~2023-12-28 로 자르면 단계 B 표 지문 `[2877771, "2023-12-28", 6700381946099, 2316557639282]` 와 정확히 같다. 이 실행의 IC 값은 스모크라 연구 결과로 쓰지 않는다.
