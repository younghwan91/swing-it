# REVIEW — 패턴 GA-FWL 1단계 설계 리뷰 (결과 전, 2026-10-11)

대상: `PATTERN_GA_FWL.md`, `git show 136463f`(`PATTERN_GA_VARIANT=fwl`), `pattern_ga_fwl/FEASIBILITY.md`.
**FW·FWL 성과 숫자는 보지 않았다.** 실행 중인 FW 파일은 건드리지 않았다.
돌린 것은 건수만 확인이다(단일 프로세스, `nice`, 스레드 1). 스크립트는 scratchpad `review_fw/fwl_*.py` 에 있다.
- x0 의 실제·2b 10벌 학습창 체결 수
- 실제 선별 앞 50만 개의 실현 가능 수(폴드 1·6)
- 열람 목록 sha·사상
- 단위 시험

판정: **그대로 실행하지 않는다.** 필수 5개다. M1·M2 는 FW 리뷰 M1·M2 와 같은 실패가 비율이 더 낮아져 다시 생긴 것이다.

## 필수 수정 (MUST — 실행 차단)

### M1. 2a: 폴드 6 은 상한 3억에서도 기대 실현 가능 수가 약 550 이다 → 2a "판단 불가 = ✗" 가 반반이다
- **위치:** `pattern_ga_run.py` `FW_FEAS_TARGET = 1_000`, `SCREEN_N` 상한 3억(FW 값 승계), `FEAS_MIN = 500`, `fw_adaptive_screen`.
- **건수:** 실제 선별 덩어리 0~9(50만 개) 실현 가능은 **폴드 6: 1 · 폴드 1: 2** 다. FEASIBILITY 5만 개(폴드 6 0, 폴드 1 1)와 합치면 비율은 폴드 6 ≈ 1.8e-6, 폴드 1 ≈ 5.5e-6 이다.
  - 폴드 6: 목표 1,000 에는 약 5.5억 개가 필요해 **상한에서 멈추고**, 그때 기대값이 약 550 이다(포아송 표본 1건이라 구간이 매우 넓다).
  - 하한 500 을 넘을지는 운이다. 넘지 못하면 2a 가 ✗ 이고, 그러면 "전 바 통과 불가" 가 메뉴가 아니라 선별 규모 때문에 정해진다.
- **수정 (결과 전 하나 고정):**
  - (a) FWL 상한을 10억/폴드로 올린다. 비경합 0.11 ms 기준 폴드 6 ≈ 30 CPU-시간이다. 폴드당 동시 6 덩어리면 약 5시간이므로, FW 종료 뒤 12코어 전부 쓰게 `per` 를 조정한다.
  - (b) FWL 에 한해 FEAS_MIN 을 300 으로 낮추고, 2a p99 가 300벌에서 분해 가능함을 문서에 적는다.
  - 어느 쪽이든 폴드별 선별 수·실현 가능 수를 결과 첫 표에 적는다.

### M2. BIPOP 재시작 풀(앞 100만)이 다시 붕괴한다
- **위치:** `RESTART_SCREEN = 1_000_000`(FW 승계), `restart_x = keep[:r_chunks]`, `null_b_task` → `restart_pool`.
- **문제:** 위 비율이면 실제 재시작 풀은 폴드 6 ≈ 2개, 폴드 1 ≈ 5개다(폴드 2~5 도 FEASIBILITY 5만 개 중 1개씩이라 비슷한 수준). FW 리뷰 M2 와 같이 모든 재시작이 한두 점에서 출발해 BIPOP 이 아니게 된다.
  2b 는 섞은 자료가 더 잘 실현 가능하다(아래 "확인한 것" 의 x0 건수 참고). 그래서 널의 재시작 풀이 실제보다 크고, 널이 더 잘 탐색한다. 판정 쪽으로는 보수적이지만, 실제 GA 가 약해져 **실패가 정보 없는 실패**가 된다.
- **수정:** 실제와 2b 에 같은 규칙을 하나 고정한다.
  - 예: "재시작 평균 = 재시작 풀(앞 100만 선별)이 ≥ 10개면 그중 균등, 아니면 x0". x0 은 실제와 2b 10벌 모두 6폴드에서 실현 가능하다.
  - 2b 에서 재시작 선별을 1,000만으로 늘리는 것은 50벌 × 6폴드 × 1천만 × 0.11 ms ≈ 92 CPU-시간이라 비현실적이다.
  - 폴드·벌별 풀 크기와 "x0 대체" 횟수를 적는다.

### M3. 체결 하한 연 6 과 바 6 의 OOS ≥ 60(≈ 연 9)이 어긋나고, 하한 쪽으로 끌리는 성질과 겹친다
- **위치:** `FLOOR_PER_YEAR, FLOOR_YEAR = 6.0, 2.0`(L5), `B6_N = 60`, 적합도 = 월 초과 블록 부트스트랩 2.5% 하단.
- **문제:**
  - 노출이 희박하면 평균과 분산이 함께 줄어 하단의 부호는 사실상 t 값이 정한다.
  - 신호가 약해 하단이 음수인 영역에서는 **체결이 적을수록 하단이 0 에 가까워진다.** 그래서 GA 는 하한(학습 3년 18건)에 붙는다.
  - 하한을 12 → 6 으로 내리면 이 끌개도 내려간다. 출력 config 가 연 6~8건 근처면 OOS(약 6.7년)가 40~55건이 되어 바 6 이 **건수로** 떨어진다.
  - 이것은 손익비·승률과 무관한 구조적 실패다. 사전 예상의 "칼날 50%" 가 이 원인일 수 있다.
- **수정 (하나):**
  - (a) 하한을 바 6 과 맞춰 연 9·연도별 3 으로 둔다. 사용자 지시 "수천 번 필요 없다" 와도 맞는다. 건수만으로 x0·FEASIBILITY 를 다시 확인한다.
  - (b) 연 6 을 유지하되 사전등록한다: 출력 config 의 학습 체결이 하한 × 1.2 이내인 폴드 수를 결과 첫 줄에 적는다. 바 6 이 n < 60 **만으로** 실패하면 "하한 결합 — 판단 불가" 로 쓰고 "기각" 이라 쓰지 않는다.

### M4. 설계에 쓴 FW 열람 내용의 공개가 부족하고, 열람 제외판이 판정에 쓰이지 않는다
- **위치:** `PATTERN_GA_FWL.md` "왜" 절, `fw_lines` 의 부모 열람 제외 줄(연환산·건수만), 바 산술.
- **문제:** L1~L3 은 FW 첫 실행의 **표본 밖 155건**을 EPS 가속·RS 별로 본 뒤 정했다. 사용자 문장 "왜 다들 힘이 없지?" 를 보면 손익도 본 것으로 읽힌다.
  FWL 의 OOS 체결은 FW OOS 사건과 크게 겹친다(같은 하락 쐐기 사건의 주도주 부분집합). 그러면 주 결과는 본 거래 중 좋았던 부분집합을 고른 것과 구분되지 않는다.
  지금은 열람 제외판이 연환산·건수 한 줄의 기술일 뿐이다.
- **수정:**
  - 문서에 FW 열람에서 무엇을 봤는지 적는다(부분군별 손익을 봤는지).
  - 바 1·6(건수·손익비·승률)을 **열람 339건 제외판으로도** 계산해 바 표에 나란히 둔다.
  - 탐색 문구의 조건을 "두 판 모두 통과" 로 사전등록한다. 제외판에는 `exclude` 로 다시 돌린 `stitched` 에서 `trade_frame` 을 만들면 된다.

### M5. 계산 계획이 없다 — FW 와 동시에 돌리면 안 된다
- **위치:** `PATTERN_GA_FWL.md` 에 시간 투영·시작 조건이 없다. FEASIBILITY 의 "5.6시간" 은 고정 3억 × 6 기준이다.
- **문제:**
  - FW 가 12코어를 쓰는 지금, 리뷰어의 건수 평가는 0.34~0.40 ms 로 비경합 0.11 ms 의 3~4배였다.
  - M1(a) 를 택하면 선별만 수 시간이다. FW 의 과구독 재시작(e1bc961)과 같은 사고가 다시 날 수 있다.
- **수정:** "FW 실행 종료 뒤 시작", 작업자 수, 스레드 환경(FW 운영 기록의 수정 그대로), 투영 시간(M1·M2 반영)을 문서에 적는다. 시작 30분 뒤 다시 투영한다는 규칙을 FW 와 같게 둔다.

## 권고 (MINOR)

1. **실현 가능성 `loose` 가 FWL 메뉴 밖이다.** `rs_min: None`·`e_min: None`·`stage: 0`(+ `pyramid off`·`be_r inf`)이라, FWL FEASIBILITY 3절 착상 영역 표는 주도주 조건이 없는 수다. FWL 이면 RS 70·e 0.25·가속·stage 3 으로 바꾸거나, 표 머리에 "주도주 조건 없음" 을 적는다.
2. **열람 목록 사상 339 중 330.** 9행은 정확한 거래일이지만 그날이 주문일인 사건이 없다. 같은 종목의 앞선 주문일(6~14 거래일 전)이 목록에 있어 **재진입 거래**로 보인다. 원 사건이 제외되므로 재진입도 함께 빠진다. 결과 문서에 "339행 = 사건 330 + 재진입 9(원 사건 경유 제외)" 를 적는다.
3. **DSR 부모 N 이 시점에 따라 달라진다.** `pattern_ga_fw`·`pattern_ga_fw_runs` 원장은 FW 실행 중에 계속 늘고, 재시작 전 중단분 줄도 섞였을 수 있다. FWL 사전등록 시점의 줄 수·고유 config 합을 상수로 고정하거나, FW 종료 뒤 값임을 적는다.
4. **`e_accel` 은 GA 정의가 SEPA 정의보다 약하다.** GA 의 '가속' 은 `e_yoy ≥ e_min ∧ e_yoy > e_yoy_prev` 뿐이다(`diagnose`·`_filter_py`). `vcp.e_accel_asof` 의 순이익·전기 > 0, 매출 YoY ≥ 10% 조건이 없다. "미너비니 주도주" 라는 이름은 이 차이를 적고 쓴다.
5. `e_accel` 단계 (1, 1)은 CMAwM 정수 축에서 안전하지만 죽은 차원이다. 축은 [0, 1] 그대로이고 두 값이 모두 1 로 복호화되며, `gkey` 가 같아 memo 를 공유하고 지형 스윕은 건너뛴다. 기술 보고의 유전자 분포에서 이 축은 빼고 읽는다.
6. 하한을 낮추면 PBO 상위 100 config 사이에 같은 체결(같은 월 계열)이 많아져 CSCV 가 퇴화할 수 있다. 고유 월 계열 수를 함께 적는다.
7. 모듈 docstring(`:12`)에 "12·연수" 가 하드코딩돼 있다. 문구만 고친다.
8. stage 2 는 6폴드 실현 가능에 한 번도 들지 못했으므로 사실상 죽은 단계다. 2a 풀에서 stage 2 비율과 GA 출력 stage 를 함께 적는다.

## 확인한 것

- **변형 연결:** `FW = VARIANT in ("fw","fwl")` 이라 F1·F2·F3·적응 선별·재시작·바 문턱·FW 머리 절이 모두 승계된다. `FLOOR_*` 재정의는 모듈 수준이고 `penalty`·`_proc_config`·FEASIBILITY 문구가 호출 시점에 읽는다.
- **`e_min`/`e_accel`/`rs_min`/`stage` 를 가정하는 경로:**
  - `canonical`: `e_min is None` 분기는 FWL 에서 도달하지 않는다.
  - `gene_vec`: RS·EMIN 은 `nz`, EACC 는 1, STAGE 는 값이다.
  - `diagnose`·`_filter_py`: stage 2/3 분기가 있다.
  - `encode`/`decode`: rs_min 이 끔 끝 없이 [70, 90] 이다.
  - 나머지: `shape_off`(주도주 유전자 불변), `median_config`(일반형), `landscape_task`(rs 6점·e_min 2단계·stage 로짓 2개), `IDEA_FLAGS`·`user_region`(무관), `STAGE_NAMES`(미사용) 모두 문제없다. 메뉴 밖 값은 `loose` 하나다(MINOR 1).
- **2a 비교 가능성:** 2a·2b·무작위 탐색·청산 대조가 모두 같은 FWL 메뉴·같은 하한이다.
- **x0:** RS 70·e 0.25 가속·stage 3·바닥 반전·θ 8%·창 120·fw_lo +0.15·h0 첫 점 0·1r·be 0.5 다.
  - 실제 학습 체결 28·45·51·57·52·39 로 전부 실현 가능하다(문서와 일치).
  - **2b 섞은 자료 rep 0~9 에서도 60폴드 전부 실현 가능**하다(37~89건, 실제보다 많다). 실제 자료에서는 하락 쐐기 표와 주도주 맥락이 음의 상관이고, 섞으면 그것이 풀린다.
  - 그래서 x0 은 2b 에서도 출발점으로 유효하다. 건수 기준으로 고른 x0 이 실제 쪽만 유리하게 하지 않는다. 오히려 널 쪽 사건이 많아 판정에 보수적이다.
- **열람 목록:** sha256 `fbb98509…` 일치, 339행 고유, 330 사상(MINOR 2). 불일치면 거부하는 코드(`:1827`)가 그대로 적용된다.
- **DSR:** `pattern_ga_fw` 원장과 `pattern_ga_fw_runs` 고유 config 가 더해진다(MINOR 3).
- **단위 시험:** `tests/test_pattern_ga_fw.py::test_fwl_variant_menu` 는 별도 프로세스에서 메뉴만 확인한다. F1 + 주도주 거르기의 `candidates` 경로 시험은 없다.
